Install once. Create once. Receipt every task. Maintain daily. That loop is the rest of the talk.

the loop

Install is not the product

  • Install the plugin once
  • /create-receipt writes .cursor/skills/verify-<app>/ — real CLI + 3–5 feature files
  • /receipt on every bug, feature, or KMP test — no proof, not done
  • /maintain-receipt daily so the map stays true to the app
  • Next agent starts cold with an honest harness
Lauren's daily /maintain-verification-skill. Ours is /maintain-receipt. Cursor Automation or a cloud agent. Not a chat cron that spams a channel.

done means files

.receipt/proof/<id>/

must exist

  • Gradle or bun output
  • JUnit XML, not a sentence
  • a PNG with PNG magic
  • logcat for the app pid

does not count

  • “tests look good”
  • any file that happens to be named .png
  • logcat ok with no process
  • assemble standing in for test
Screenshot is capture-only by default. --install and --launch are opt-in. ok = every step exit 0 AND \x89PNG. logcat uses pidof the package. App not running → ok: false.

honest CLI

The commands that cannot flatter

cd sample
./verify doctor
./verify test
./verify assemble
./verify screenshot --install --launch   # cold start
./verify screenshot                      # current frame only
./verify logcat                          # pidof the package

JSON. --dry-run. --help. AdbHarbor lease if present — never --force. Proof survives cleanup.

If you increment the counter then screenshot with --launch, you get Counter 0. That is why capture-only is the default. We have a proof PNG that shows Counter 1 because we did not relaunch.
