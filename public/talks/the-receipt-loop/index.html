The Receipt Loop

Somu
7–8 October 2026 · Chetpet
Day 1: Make agents trustworthy in our repos
Day 2: Orchestrate, don't prompt

This board is the presentation. Showcases are terminal, repo, CI, app, and cloud evidence.

A claim becomes a receipt.

A receipt becomes a rule.

A rule becomes a rail.

An agent does not get to say done until it leaves a receipt. Stripe, Poteto, and the Grok Bot team are their results, not our rate.

Four words

  • ClaimA message. "Done."
  • ReceiptAn artifact. Output, screenshot, log, CI run.
  • RuleA receipt that stays. A test, a check, an eval.
  • RailA rule that runs unattended.

Trust is not a feeling. It is an artifact.

The gap

Self-verification.

Most teams have skills. Few can prove a change works without a human.

The remedy is not more prompts. It is an executable verification loop. Badge: Recorded.

Intent

One ticket. One command that can fail.

Acceptance is a command, not a paragraph. ./verify

Demo: cat AGENTS.md, then ./verify test. Badge: Live. PR #162 at e480eb2 is unmerged. ./verify is the interface. The skill directory is not auto-loaded.

Isolated execution

A ticket goes in. A sandbox comes up.

A person starts it. The finish can be automatic. 100 agents without proof is slop.

Badge: Recorded. PR #165. Launch is human. Completion webhook to Buzz is proven. A monitoring trigger that starts a run is not proven.

Evidence

A cold launch is not proof.

A driven path is. The receipt survives cleanup.

Badge: Recorded. Exact CI APK on Nothing Phone (3). Cold start 672 ms. Detail shows User #1.

Review

The author is not the reviewer.

A reviewer that cannot merge is a control, not a rubber stamp.

Badge: Recorded. Report PR #166. Vedha validated it as workshop evidence. Green automation badges are status, not reviews.

Eval

An eval is not an app test.

Correct is not the same as good. Neither is the same as fresh.

Label: eval in CI (replay mode). 12 cases. A replay is recorded. A live model run is a separate gate.

Merge

A human decision, sized by blast radius.

  • LowNo shared contract. Easy to revert.
  • OwnedOne team's code. A receipt is attached.
  • Blast radiusShared library, schema, auth, or infra.
Badge: Prepared. RISK_TIERS.md and CODEOWNERS are in unmerged PR #162. Branch protection on main is absent.

Correction

A failure becomes a rule.

A fix that is not recorded is a fix you will make again.

Badge: Live. Label: staged red check. PR #163 failed on User #1, then the fix went green.

Where it lives

Write it as low as it goes.

  1. Codebase
  2. Required check, lint, compiler
  3. Eval
  4. Rules and AGENTS.md
  5. Skill and verify command
  6. Style guide

Prompt memory does not survive. The repo does.

Stock detekt runs. No custom lint rule. The staged test is a real CI check, not an always-red check.

Debt

No promise of zero debt.

A path for every correction, and an owner. A gardener run does not exist yet.

Known gap. Dependabot PRs sit unattended. That is the debt, not a cleanup that ran.

The map

A map that rots is worse than no map.

Better memory makes the next intent cheaper.

Badge: Recorded. Maintain pass PR #167. Vedha returned SHIP. The pull request is unmerged, so it is not on main.

Automation raises the ceiling.

Proof and review set the safe one.

Higher throughput with evidence. Not a bug-free guarantee.

Poteto's 2,000 pull requests in a month is her case study, not our target. 100 agents without proof is slop.

The bar

An intern and Claude can navigate the repo.

  • A verify command exists
  • It drives one real user path
  • The evidence survives cleanup
  • A required check runs it
  • AGENTS.md says how to reach each feature
Day 1: every repo has a verify command and one green required check. Day 2: one workflow, an owner, and a gap to close.
